# Footer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the site-title-only footer with a discovery-led footer offering Science Series links, a dynamic category list, and an identity strip.

**Architecture:** The six Science Series page paths move from `patterns/header-navigation.php` into a shared `inc/navigation.php` resolver so header and footer read one list. Two new non-inserter patterns supply the footer's translated content; `parts/footer.html` composes them inside the existing full-width group. Categories come from the Core Categories block. A new `assets/css/footer.css` arranges the flat `<ul>` Core emits.

**Tech Stack:** WordPress block theme, `theme.json` v3, PHP 7.4+, no build step, no JavaScript, no test framework.

## Global Constraints

- WordPress 6.6 minimum; PHP 7.4 minimum.
- No new editorial copy. Region headings reuse existing shipped strings verbatim: `அறிவியல் தொடர்கள்` and `பிரிவுகள்`.
- The only new string is the copyright format `© %1$s %2$s`.
- Text domain is `parimaanam-2026`. All source strings are Tamil. Translation calls must receive string literals, never variables.
- No hard-coded page IDs, term IDs, or production URLs.
- Escape at the output boundary: `esc_url`, `esc_html`, `esc_attr`.
- Bump `Version:` in `style.css` whenever files in `patterns/` change; WordPress caches the pattern list against it.
- Footer headings are `h2`. No `h1` in the footer.
- No Tailwind, no framework, no build tooling, no JavaScript.

## File Structure

| File | Responsibility |
| --- | --- |
| `inc/navigation.php` | Owns the approved page-path map and path→URL resolution. |
| `functions.php` | Requires `inc/navigation.php`; enqueues `assets/css/footer.css`. |
| `patterns/header-navigation.php` | Consumes the shared resolver. Labels stay here. |
| `patterns/footer-discovery.php` | Series list and category list, with headings. |
| `patterns/footer-meta.php` | Site title, copyright, conditional privacy link. |
| `assets/css/footer.css` | Footer layout only. |
| `parts/footer.html` | Outer group and pattern composition. |

## Verification tooling

There is no unit test framework. Substitute gates, used throughout:

- **Lint:** `php -l <file>`
- **Render:** execute a PHP heredoc inside the running container, which boots WordPress and runs `do_blocks()` on a registered pattern, then asserts on the HTML.
- **DOM:** browser assertions against `http://localhost:8080`.

- [ ] **Step 2: Create the resolver**

```php
<?php
/**
 * Shared resolution of approved page paths to URLs.
 *
 * The header and the footer both link to the same approved pages. Keeping one
 * path list here prevents the two from drifting apart.
 *
 * @package Parimaanam_2026
 */

/**
 * The approved hierarchical page paths used by site navigation.
 *
 * @return array<string, string> Stable key => page path.
 */
function parimaanam_2026_navigation_paths() {
	return array(
		'science-series'                 => 'science-series',
		'black-holes-series'             => 'science-series/black-holes-series',
		'artificial-intelligence-series' => 'science-series/artificial-intelligence-series',
		'extraterrestrial-civilizations' => 'science-series/extraterrestrial-civilizations',
		'large-hardon-collider'          => 'science-series/large-hardon-collider',
		'hubble-space-telescope'         => 'science-series/hubble-space-telescope',
		'electromagnetic-waves'          => 'science-series/electromagnetic-waves',
		'downloads'                      => 'downloads',
		'free-ebooks'                    => 'downloads/free-ebooks',
		'contacts'                       => 'contacts',
		'about'                          => 'about',
	);
}

/**
 * Resolve an approved page key to a URL.
 *
 * Falls back to an installation-relative URL when the page is absent, so the
 * theme stays portable across environments and installation paths.
 *
 * @param string $key Key from parimaanam_2026_navigation_paths().
 * @return string Resolved URL, or an empty string for an unknown key.
 */
function parimaanam_2026_navigation_url( $key ) {
	$parimaanam_paths = parimaanam_2026_navigation_paths();

	if ( ! isset( $parimaanam_paths[ $key ] ) ) {
		return '';
	}

	$parimaanam_page = get_page_by_path( $parimaanam_paths[ $key ] );

	if ( $parimaanam_page instanceof WP_Post ) {
		return (string) get_permalink( $parimaanam_page );
	}

	return home_url( trailingslashit( $parimaanam_paths[ $key ] ) );
}
```

- [ ] **Step 1: Create the pattern**

`get_the_privacy_policy_link()` returns an empty string unless a privacy page is both designated and published, and it supplies its own escaped anchor using the page's title. That gives the conditional behaviour for free, with no invented link text.

```php
<?php
/**
 * Title: Footer meta
 * Slug: parimaanam-2026/footer-meta
 * Inserter: no
 */

$parimaanam_privacy_link = get_the_privacy_policy_link();
?>

<!-- wp:group {"className":"site-footer__meta","style":{"spacing":{"blockGap":"var:preset|spacing|40"}},"layout":{"type":"flex","flexWrap":"wrap","justifyContent":"space-between"}} -->
<div class="wp-block-group site-footer__meta">
	<!-- wp:site-title {"level":0,"isLink":true,"fontSize":"small"} /-->

	<!-- wp:paragraph {"className":"site-footer__copyright","fontSize":"small"} -->
	<p class="site-footer__copyright has-small-font-size"><?php
		printf(
			/* translators: 1: four-digit year, 2: site name. */
			esc_html_x( '© %1$s %2$s', 'Footer copyright line', 'parimaanam-2026' ),
			esc_html( wp_date( 'Y' ) ),
			esc_html( get_bloginfo( 'name' ) )
		);
	?></p>
	<!-- /wp:paragraph -->

	<?php if ( '' !== $parimaanam_privacy_link ) : ?>
	<!-- wp:paragraph {"className":"site-footer__privacy","fontSize":"small"} -->
	<p class="site-footer__privacy has-small-font-size"><?php echo wp_kses_post( $parimaanam_privacy_link ); ?></p>
	<!-- /wp:paragraph -->
	<?php endif; ?>
</div>
<!-- /wp:group -->
```
